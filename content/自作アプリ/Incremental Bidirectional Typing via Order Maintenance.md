# Analysis Plan: Incremental Bidirectional Typing via Order Maintenance

Generated by claude code
## Paper Overview

**Title:** Incremental Bidirectional Typing via Order Maintenance **Authors:** Thomas J. Porter, Marisa Kirisame, Ivan Wei, Pavel Panchekha, Cyrus Omar **Publication:** OOPSLA 2025 (October 2025) **Institutions:** University of Michigan, University of Utah

## 1. Core Problem Statement

### Research Question

How can type information be incrementally maintained in live programming environments to provide continuous semantic feedback without re-analyzing the entire program after each edit?

### Motivation

- Traditional batch compilation struggles with live programming demands
- Users need continuous type feedback while editing incomplete/erroneous programs
- Large codebases (multi-million lines, "planetary-scale") make full reanalysis prohibitive
- Goal: type checking that doesn't block editing, even for large programs

## 2. Key Technical Contributions

### 2.1 Marked and Annotated Lambda Calculus (MALC)

- **Extension of MLC:** Builds on the Marked Lambda Calculus by Zhao et al. [50]
- **Key modifications:**
    - Boolean marks instead of term constructors for errors
    - Every term annotated with analyzed and synthesized types
    - Simplifies error marking specification
    - Supports total type error localization

### 2.2 Incremental MALC

- **Small-step update propagation dynamics**
- **Dirty bits:** Types marked as ★ (dirty) or • (clean)
- **Update propagation frontier:** Tracks where updates need to flow
- **Key properties:**
    - Updates flow bidirectionally (left-to-right in syntax)
    - Actions and updates can be interleaved
    - Correctness guaranteed when quiescent (no dirty bits)

### 2.3 Implementation: Malcom

- **Order maintenance data structures:** O(1) insertion and comparison
- **Timestamps:** Pre-order and post-order intervals for containment testing
- **Variable/binder pointers:** Direct connections, no traversal needed
- **Splay trees:** Efficient binding scope management
- **Priority queue:** Ordered update propagation

## 3. Theoretical Foundations

### 3.1 Type System Base

- **Bidirectional typing:** Analysis (⇐) and synthesis (⇒) modes
- **Gradual typing:** Unknown type (?) for incomplete programs
- **Type consistency:** Allows ? to match any type

### 3.2 Metatheory (Agda-verified)

**Theorem 5.1 (Validity):** Incremental analysis produces correct results w.r.t. MALC **Theorem 5.2 (Convergence):** Update order doesn't affect final result **Theorem 5.3 (Termination):** No infinite update sequences

### 3.3 Action Calculus

- **Structure editor actions:** Insert, delete, wrap, unwrap
- **Fine-grained edits:** At expression level
- **Action completeness:** Any program reachable from any other

## 4. Implementation Architecture

### 4.1 Data Structures

```
- Mutable tree representation with parent pointers
- Timestamps: (a, b) where a = pre-order, b = post-order
- Order maintenance structure for O(1) operations
- Variable → Binder pointers
- Binder → Set<Variable> (splay tree)
- Global map: VarName → Set<Binder> (splay tree)
- Priority queue for dirty types
```

### 4.2 Key Algorithms

1. **Variable insertion:** O(log n) binder lookup via splay tree
2. **Binder insertion:** Splay tree splitting for shadowing
3. **Update propagation:** Pop from queue, update locally, push new dirty locations
4. **Binding updates:** Direct pointer traversal, no tree traversal

### 4.3 Optimizations

- **Unchanged type optimization:** Don't dirty if type stays same
- **Timestamp-based prioritization:** Upstream before downstream
- **Deleted term handling:** Skip updates to deleted nodes

## 5. Evaluation Results

### Benchmark Design

- **Stress test:** 100 nested merge sort implementations
- **Tests:**
    - Shadowing (100 levels of mergesort binding)
    - Name reuse (split_n, merge_n variables)
    - Random edits (500 operations)

### Performance

- **275.96× speedup** vs. from-scratch analysis
- **Algorithmic improvement:** Near-constant time regardless of program size
- Most edits: multiple orders of magnitude speedup
- Some edge cases: binding structure changes show slight growth

## 6. Novel Technical Insights

### 6.1 Order Maintenance for PL

**Innovation:** Applying web browser layout techniques to type checking

- First use of order maintenance for incremental type systems
- Timestamps encode containment and traversal order
- O(1) operations for critical path

### 6.2 Binding Management

**Challenge:** Non-local effects of variable/binder edits **Solution:**

- Direct pointers + splay trees
- Split/join operations for shadowing
- No full tree traversal needed

### 6.3 Bidirectional Flow

**Design principle:** Information flows left-to-right

- Analyzed types: pre-order propagation
- Synthesized types: post-order propagation
- Priority queue respects this order

## 7. Limitations and Future Work


This paper makes a significant contribution to live programming by providing the first theoretically grounded and practically efficient solution for incremental bidirectional type checking. The combination of:

1. Formal semantics (Incremental MALC)
2. Mechanized metatheory (Agda proofs)
3. Novel implementation techniques (order maintenance, splay trees)
4. Strong empirical results (275× speedup)
